## 4. Architecture recommendation

Stay on modular vanilla JS plus Vite by default. A TypeScript or framework migration is not justified for this codebase size and adds Termux toolchain weight; choose it only if the Phase 10 spike shows hand-rolled targeted rendering cannot meet the acceptance checks. The actual fix is render strategy plus API layer: targeted per-region renderers (sidebar, list, detail, modals) instead of full `#app` rebuilds; keyed DOM patching; a central abortable, deduped, version-stamped API client; splitting dashboard state into UI state vs server data; SSE with polling fallback.

## 4A. Recommended Agent Runner — Node supervisor + Muse CLI (verified help surface, no framework rewrite by default)

Verified CLI surface (help only, no live inference, no secrets): `muse --help` lists `exec`, `resume`, `export`, `trace`, `model-profile`, `sandbox`, `mcp`, `auth`; `muse exec --help` shows headless flags `--prompt-file`, `--json` JSONL, `--provider echo|meta`, `--model`, `--contributor-mode on|off`, `--output-schema FILE` (meta only), `--max-model-steps N`, `--max-tool-output-bytes`, `--session-id UUID`, `--permission-profile`, `--workspace`, `--worktree`, `--approval-mode`, `--disable-*`, `--reasoning-effort`; `muse resume --help` is `resume --last|<session-ref>` (exact UUID or Session Name, picker with no arg) — interactive TUI resume, not verified headless continuation; `muse export --help` is offline transcript export (`export_schema_version 1`, `--session <id|path>|--last`, `--out`, `--redacted`, no network); `muse model-profile --help` is `show <model> [--effort tier]` (e.g. `muse-spark-1.3`, tiers none..ultra) — values unverified until `show` spike; `muse trace --help` exposes `trace inspect` only at top level. `--session-id` alone is not resume; Fresh/Resumed/transcript claims require a proven local session log / export, otherwise UI states provenance as unavailable. `--output-schema` shape is unverified live (no inference performed).

Use ONLY the current native Meta contributor model (repo CLI id `muse-spark-1.3` with `--contributor-mode on`); no other children/subagents by default. The VS Code selection `muse-spark-1.3-contributor` is a different interface — do not assert identical CLI id support or force the same model ignoring the configured agent. Resolve configured agent provider/model overrides but default Meta; fail closed on disallowed provider with no Azure silent fallback.

Lifecycle/contract (supervisor owns truth): Node supervisor resolves the configured agent, builds prompt+context, assigns IDs/version/attempt/session/agent/model plus result path `data/responses/<runId>/step<N>.json` (constrained safe strings, fixed root, no injection/symlink escape), spawns `muse exec` with scoped permissions/tools and wall-clock/token/model-step/tool budgets, and cancels via process-tree kill (platform specifics caveat). Model may tool-write a draft in its allowed path, but supervisor owns the final envelope via atomic write+rename (file valid before rename). Inbox `pending`/`open` + `running` are authoritative in SQLite; the filesystem watcher is a hint only (fixed root, startup + periodic scan). Result envelope terminal statuses are `done|blocked|failed|cancelled`; supervisor computes hash externally and stores a DB reconcile marker — never a self-referential `fileHash` inside hashed content, never mutate an immutable final to mark reconciled. Distinguish natural model payload (`summary`/`output`/`status`) from the trusted supervisor envelope. Idempotency via expected assignment/result hash in a transaction; cancellation races compare terminal state; an expired lease never blindly redispatches side effects.

Candidates: (A) Node `child_process.spawn` + `muse exec` — recommended default, keeps the existing full tool harness (`src/agent.js` path), no new deps. (B) Vercel AI SDK `generateText`/`ToolLoopAgent` — implements the model tool loop in-process with `stopWhen`/`prepareStep`/`Output.object`, plus `HarnessAgent` for existing harnesses; needs a custom `LanguageModel` adapter for Meta/Muse, no durable checkpoints alone — [agents overview](https://ai-sdk.dev/docs/agents/overview), [generateText](https://ai-sdk.dev/docs/reference/ai-sdk-core/generate-text). (C) LangGraph JS — durable checkpoints/persistence and prebuilt agents, but extra deps plus custom model adapter plus Termux weight unverified — [persistence](https://langchain-ai.github.io/langgraphjs/concepts/persistence/). (D) Mastra Agent/workflows/memory/structured-output / Temporal — custom providers/adapters possible but need validation; Mastra model-router `provider/model` plus heavy TS toolchain, Temporal infra unsuitable for single-tablet SQLite — [agents](https://mastra.ai/docs/agents/overview), [models](https://mastra.ai/models). Do not assert categorical Meta incompatibility. Architecture: stay on (A) by default; adopt B/C/D only if Phase 1/10 spikes prove a gap. `fs.watch` vs optional `chokidar`: `fs.watch` coalesces/misses across atomic rename on Linux/Termux — mitigate with fixed-root watch plus startup/periodic rescan plus SQLite authority; spike `chokidar` only if flakiness blocks acceptance. Existing `node:sqlite` stays (built-in, no new dep). Node 22 target runtime unverified until acceptance gates.

Sandbox policy gets a review write-up with no claim of current safety. PR/ADO integrations are out of scope — no adapters, no sweep, no PR link/filter feature.
